- **2026-11-25** — An advisor: a second model the agent can consult mid-task. With `advisor.model` set in config (on `advisor.provider`, else the default provider), `--advisor [provider:]model` on `agent`, `tui`, `gateway` and `serve`, or `/advisor` in the REPL and the TUI, the agent gets an `advisor` tool that takes a `question`. The advisor is sent a system prompt that makes it a brief second-opinion reviewer, a condensed transcript of the conversation (user and assistant text, tool calls with their arguments, tool results; the oldest part cut to `advisor.max_context_chars`, 60,000, with a note saying so, and the user's latest message always kept) and the question, with no tools, through the ordinary provider factory; its answer is the tool result. Read-only, so plan mode and parallel batches allow it; at most `advisor.max_calls_per_turn` (3) calls a turn, counted per loop, so each subagent turn has its own; subagents inherit it through `"tools": ["*"]`. `--no-advisor` and `/advisor off` take the tool out of the next request. Its tokens go to a stats bucket per advisor provider and model, so `/v1/stats` credits the advisor's model, not the session that asked. The tool loop gained `CurrentDispatchHistory` / `BumpTurnCounter`, a tool's view of the turn it runs in. Reviews nobody asked for (OpenClaw's style) are not here. See `docs/advisor.md`.
- **2026-11-25** — The MCP client speaks MCP 2026-07-28 and still connects to older servers. It probes with `server/discover` and, for a modern server, sends no `initialize` and no session: every request carries `_meta` (protocol version, client info, capabilities) and, over HTTP, `MCP-Protocol-Version`, `Mcp-Method`, `Mcp-Name` and `x-mcp-header` headers. An error, an HTTP 4xx, silence or `UnsupportedProtocolVersionError` falls back to `initialize` (offering 2025-11-25, accepting what the server answers); 2024-11-05, 2025-06-18 and 2025-11-25 servers connect as before. The negotiated version shows in `pasclaw mcp test`, `GET /v1/mcp` and the web UI's MCP tab. Servers can ask the user for input: multi round-trip `input_required` results and legacy `elicitation/create` (stdio) are answered at the keyboard in the `pasclaw agent` REPL and the FPC `pasclaw tui`, one typed prompt per form field, a URL shown but never opened; the gateway, one-shot runs and subagents declare no elicitation and decline, telling the model what was asked and handing it the URL. Tool calls that become tasks (`io.modelcontextprotocol/tasks`) are polled with `tasks/get` within the call's timeout, with task input sent by `tasks/update`. OAuth: the authorization response's `iss` is checked (RFC 9207), dynamic registration declares `application_type: native`, a stored client is reused only with the issuer that registered it, and a Client ID Metadata Document is used when the server supports one and `mcp_oauth_client_metadata_url` is set. Also fixed: an HTTP JSON reply that mentions `data:` (an icon's data URI) was taken for an event stream and lost, and the client sent two `Accept` headers. Sampling and roots (deprecated) are not offered; skills over MCP are not implemented yet. See `docs/mcp.md`.
- **2026-11-21** — `make xp` builds the full `pasclaw.exe` for 32-bit Windows with Free Pascal, made to load on Windows XP. - **2026-11-21** — PasClaw on DOS. `PCLAW.EXE` (`src/dos`, `make dos`) runs the agent loop and its tools on an MS-DOS PC (486 or later; it ran in 2 MB in DOSBox-X): `read_file`, `list_dir`, and `write_file`, `edit_file` and `run` (through `COMMAND.COM`), each of the last three asked about first unless `/YES`. A DOS PC has no TCP/IP or TLS, so each model call goes as plain HTTP/1.1 down a serial line to the new `pasclaw bridge` (`--serial /dev/ttyUSB0` or `COM3` for a null-modem cable, `--listen` for DOSBox-X's `serial1=nullmodem ... transparent:1`), which forwards it to a gateway's `/v1/responses` with the tools passed through, so the model's tool calls come back to DOS to run. The gateway token and provider keys stay on the modern machine; the bridge forwards only `POST /v1/responses`, `GET /v1/health` and `GET /v1/models`, sends this config's token only to this config's gateway, and cuts each answer down to what the client reads (2.6 KB to about 0.5 KB a step). Every body carries a CRC-32 and every request a sequence number, so a damaged request or answer is sent again and a late one skipped. The screen, keyboard, files and file names are CP437 with CR LF and the client converts at each edge. `make dos-toolchain` builds the i386 cross compiler from `fpc-source` and fetches the DOS units; `make test-dos` runs the bridge and a host build of the client against a real gateway over TCP and a pseudo-terminal pair, and `make test-dos-dosbox` runs `PCLAW.EXE` in DOSBox-X. See `docs/dos.md`.
- **2026-11-13** — `pasclaw agent -m "..." --session ID` is a turn on that session. - **2026-11-13** — A provider refusal is an error, not the assistant's reply. `/v1/chat/completions` used to return the provider's error text as an HTTP 200 answer, and `PersistGatewaySession` saved it as an assistant message, so on the next turn the model was told it had said it. - **2026-11-12** — `pasclaw acp` runs PasClaw as an [Agent Client Protocol](https://agentclientprotocol.com) agent, so an editor (Zed, JetBrains IDEs, ACP plugins for Neovim and Emacs) can drive it over newline-delimited JSON-RPC on stdin and stdout, with the same loop, tools, `permissions` rules, sessions, modes and providers as `pasclaw agent`. The editor gets each tool call with its kind, title and file location, a before/after diff for `write_file` / `edit_file` / `append_file`, `todo_write` as a `plan`, `ask` rules as `session/request_permission` (Allow once / Allow for this session / Deny), `session/cancel`, the four modes through `session/set_mode` (which now reaches the system prompt after the first turn, as the REPL's `/mode` now does too), and `session/load` replay.
